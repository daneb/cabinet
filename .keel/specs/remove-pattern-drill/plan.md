# Design — remove-pattern-drill

## Approach

Add a `drillable` flag to each entry in `CATEGORIES` in `patterns-data.js`
(`false` for `mate` and `endgame`) — that is the seam: one piece of data
drives both the test oracle and the panel's render decision, so there is
nothing to keep in sync by hand. `patterns-panel.jsx` looks up the category's
`drillable` flag when rendering each row's action buttons and skips the
"Drill" button (and its `handleDrill` call) when it is `false`; "View" always
renders. `onDrillPattern`, `handleDrillPattern`, `useDrill` and
`PatternsProgress` in `app.jsx` are untouched — they still exist for the
repertoire drill feature and for a future drillable category.
